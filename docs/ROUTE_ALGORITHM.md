# 도보 코스 추천 알고리즘

기준: 2026-10-26 현재 코드. 사용자가 장소와 순서를 정하는 규칙 기반 추천입니다. 과거 5곳 순열 전수탐색·TSP 정확해 설명은 현재 구현에 적용되지 않습니다.

## 순차 선택 API

`POST /api/recommend/next`: `start_lat`, `start_lon`, `stop_ids`, `category`, `max_minutes`, `return_to_start`를 전달합니다. `category`가 없으면 선택한 코스만 재계산합니다. 운영 입력은 `data/processed/fin/places.csv`입니다. `departure_date`(`YYYY-MM-DD`)·`departure_time`(`HH:MM`)은 선택값이며, 생략하면 한국시간 현재 날짜·시각을 씁니다 — 영업시간 판정([장소 스키마](PLACES_SCHEMA.md#요일별-영업시간))에 쓰며, `closed`로 확인된 장소는 아래 4단계에서 신규 후보·대체 목록에서 제외됩니다.

1. 입력 범위와 ID 존재·중복을 검사하고 기존 선택 순서를 유지합니다.
2. 선택한 업종에서 이미 고른 장소를 제외합니다.
3. 마지막 장소(첫 선택은 출발지)와의 직선거리로 후보 풀을 좁힙니다. 기존 규칙상 카테고리당 최대 20곳이며 같은 업종의 30m 미만 근접 장소를 줄입니다. 같은 건물의 다른 가게가 누락될 수 있습니다.
4. 영업정보가 `closed`로 확인된 후보를 제외합니다(`route.py`의 `_is_closed()`). `unknown`·`open`은 그대로 남습니다.
5. TMAP 보행자 경로를 확인합니다. 직전 장소(첫 선택은 최초 출발지)에서 1,200초를 넘는 장소는 제외합니다. 반올림한 표시 분이 아니라 초로 검사합니다.
6. 추가 후 전체 도보·체류·선택한 복귀시간을 계산합니다.
7. 전체 일정이 설정 시간 +10분을 넘는 후보는 제외합니다. 시간 내 후보를 먼저 배치하고, 부족하면 허용 범위 내 초과 후보를 경고와 함께 채웁니다. 각 그룹 안에서 [노출 순환](recommendation_rotation.md)을 적용해 최대 3곳을 반환합니다.

전체 시간 = 출발지→첫 장소 + 장소 사이 도보 + 각 장소 기본 체류시간 + 선택한 경우 마지막 장소→출발지 도보.

## 제한과 경고

| 항목 | 처리 |
|---|---|
| 직전 장소→다음 장소 | 도보 20분 이내(첫 장소는 최초 출발지 기준) |
| 중복·알 수 없는 ID | 거절 |
| 선택 장소 수 | 최대 24곳 |
| 업종별 방문 횟수 | 제한 없음. 전체 장소 수 한도 내에서 사용자가 선택 |
| 설정 여행시간 초과 | +10분까지 경고 후 허용, 그보다 초과하면 후보 제외·재계산 거절 |

360분은 여행시간 입력 최댓값이며 실제 코스 합계의 강제 상한이 아닙니다. 304분 사용 후 체류 60분·도보 5분 카페를 추가하면 총 369분, 9분 초과 경고가 나옵니다. `POST /api/recommend/recalculate`에도 +10분 한도를 적용합니다. 선택한 복귀시간은 전체 시간에 포함하며, 복귀 구간 자체에는 20분 제한을 적용하지 않습니다. 판정은 표시용 반올림 전 초 단위로 수행합니다.

## 순환과 검증 범위

초기 이동 유사 범위는 각 그룹의 최단 이동시간 + 120초입니다. 최근 7일 1위 노출 수 → 전체 목록 노출 수 → 도보 초 → 장소 ID 순으로 배치합니다. 2분은 초기 운영값이며 최적값으로 검증되지 않았습니다.

목록 영역의 표시 확인을 받은 뒤 한 번만 집계합니다. 후보 자격을 얻은 횟수·클릭·선택·실제 방문은 아직 저장하지 않습니다. 노출 기회 분산이 경제적 효과를 입증하지는 않습니다.

호환 API `POST /api/recommend`는 기존 탐욕적 자동 초안 방식으로 시간 내에서 구성합니다. 현재 순차 선택 화면의 중심 API는 아니며 프런트엔드도 호출하지 않습니다. `departure_date`/`departure_time`·`opening_status`는 이 API와 `POST /api/recommend/recalculate`에는 아직 없고 `/next`에만 있습니다. 모든 장소 전수 비교나 전역 최적 경로를 보장하지 않습니다.

TMAP은 예상 도보시간이며 체류시간은 유형별 초기 가정입니다. 요청 내 경로만 캐시하고 지속 저장하지 않습니다. 가까운 후보들을 실제 도보로 확인하므로 API 호출·지연이 늘 수 있습니다. 영업시간은 `closed`로 확인된 신규 후보만 제외하고, 응답에는 어떤 경우든 `opening_status`(`open`/`closed`/`unknown`) 안내 태그를 함께 붙입니다. 사용자가 이미 코스에 넣은 장소는 이후 `closed`로 확인돼도 자동으로 빠지지 않습니다. 평점·리뷰 가중치·강화학습도 운영 추천에 사용하지 않습니다.
